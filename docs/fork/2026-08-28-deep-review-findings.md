### 1. [CRITICAL] `Tab::pane_count` ignores `saved_layout`, so zoom silently destroys panes
**Location:** `src-app/src/workspace/tab.rs:74`; ingress `app/event_handlers.rs:676`, `:874`,
`app/ipc_handler.rs:3311`, `app/launch_pad.rs:254`, `:514`
**Problem:** `pane_count` reads only `self.root`. Under zoom the real tree lives in
`tab.saved_layout` and `root` holds just the zoomed pane, so it reports 1 and
`can_add_pane()` is effectively unconditional. `exit_zoom` then does `self.root = Some(saved)`,
discarding anything added meanwhile. Every sibling accessor (`contains_pane`, `any_pane`,
`collect_panes`, `serialize`) already consults both.
**Why it matters:** Zoom a pane, drag an agent onto its edge, unzoom — the pane, its PTY and
the running agent vanish with no error. The launch-pad path creates a git worktree first, so
the worktree is orphaned on disk. IPC replies `{"split": true}` for a pane that will disappear,
and `MAX_PANES` can be exceeded.
**Suggested fix:** Mirror `serialize`'s precedence: `saved_layout.as_ref().or(root.as_ref())`.
Add the `is_zoomed()` refusal the keyboard paths already have (`event_handlers.rs:946`,
`workspace_ops/mod.rs:1484`, `:1530`) to all five ingress sites. For IPC use `tab.is_zoomed()`
on the *resolved* tab — `Workspace::is_zoomed()` only checks the active one.
**Verification:** Unit test: build a zoomed tab with N panes in `saved_layout`, assert
`pane_count() == N` and `can_add_pane()` is false at the cap.

### 2. [CRITICAL] IPC coerces a malformed `index` into "the active workspace"
**Location:** `src-app/src/app/ipc_handler.rs:2741`; same shape `:2726`, `:3039`, `:3171`, `:1759`
**Problem:** `params.get("index").and_then(|i| i.as_u64()).map(|i| i as usize).unwrap_or(self.active_idx)`.
`as_u64()` returns `None` for a string `"2"`, a float `2.0`, a negative, or `null` — all fall
through to the active workspace, and the reply reports success.
**Why it matters:** One quoting mistake in an orchestration script closes the *wrong* workspace —
every pane, PTY and managed worktree it owns — or injects text into the wrong agent.
**Suggested fix:** Distinguish absent from malformed at all five sites, following
`requested_workspace_id` in the same file at `:1084`, which returns `-32602 invalid_params`.
**Verification:** Send `{"index": "2"}` over IPC; expect `-32602`, not a close.

### 4. [HIGH] A waiting agent with no message text shows no attention indicator
**Found by:** Software Architect (headline finding)
**Location:** `src-app/src/app/ipc_handler.rs:2574`
**Problem:** `waiting` is `HashMap<u64, Option<String>>`. `read_notification_message` (`:262`)

`pane.rs:1485` and `:2075` gate the ring, dot and badge on `attention.is_some()`.

### 5. [HIGH] Rebinding any shortcut in Settings on macOS breaks it permanently
**Location:** `src-app/src/app/settings.rs:316`
**Problem:** `event.keystroke.to_string()`. GPUI's `Display` emits **HIG glyphs** under
`cfg(target_os = "macos")` (`keystroke.rs:684-698`: `^`, `⌥`, `⌘`), so Cmd+Shift+D is recorded
as the literal `"⌘⇧D"`. `save_shortcut_checked` (`config_writer.rs:357`) performs no keystroke
validation and writes it verbatim to `paneflow.json`. The correct inverse exists and is
documented as such: `Keystroke::unparse()` at `keystroke.rs:223`.
**Why it matters:** The destructive half is `keybindings/apply.rs:132` —
`.filter(|d| !remapped_actions.contains(d.action_name))` is keyed on the *action name*, so the
real default is dropped while the override registers a keystroke no event can produce. The
action becomes unreachable from the keyboard and persists broken across restarts. The Settings
UI still renders the row correctly, so there is no signal.
**Suggested fix:** `event.keystroke.unparse()`.
**Verification:** Regression test must assert the round-tripped keystroke *equals* the recorded
one — parse-success alone passes today.

### 7. [HIGH] Git probes honor the repo's own `.git/config` — code execution from a hostile repo
**Found by:** Security Architect (H1)
**Location:** `src-app/src/workspace/git.rs:111`, `src-app/src/diff/git.rs:159`,
`src-app/src/workspace/worktree.rs:601`, `src-app/src/app/diff_dock/branch.rs:487`, `:515`
(9 bare `Command::new("git")` sites total). Trigger: `app/bootstrap.rs:318`.
**Problem:** `git_stdout` sets exactly one hardening var, `GIT_TERMINAL_PROMPT=0`. A repo-wide
grep for `GIT_CONFIG_NOSYSTEM`, `core.fsmonitor`, `hooksPath`, `diff.external` returns **zero**
hits; `git -c` is never used in production. `git diff --shortstat` and `git ls-files --others`
both refresh the index, so both execute `core.fsmonitor`.
**Why it matters:** A repo delivered as a tarball/zip carries `.git/config` (unlike `git clone`).
Opening it gives code execution as the user *inside the PaneFlow process* on the branch-badge
refresh — a background poll, no user action. For an already-compromised agent this is a sandbox
escape: execution leaves the pane and bypasses the agent's own permission gating.
`core.pager` is not reachable (stdout is a pipe).
**Suggested fix:** One shared prelude on all sites:
`-c core.fsmonitor= -c core.hooksPath=/dev/null -c diff.external=`, plus `env_remove` for
`GIT_DIR`/`GIT_WORK_TREE`/`GIT_SSH_COMMAND`/`GIT_CONFIG_COUNT`. Collapse the near-duplicate
helpers into one so the hardening cannot drift. Also add the missing `GIT_TERMINAL_PROMPT=0`
to `worktree.rs:601`.
**Verification:** Test asserting every git invocation carries the prelude.

### 8. [HIGH] User-writable dirs are prepended ahead of `/usr/bin`, then `git` is resolved by name
**Found by:** Security Architect (H2)
**Location:** `src-app/src/runtime_paths.rs:208-209`, called from `main.rs:2481`
**Problem:** `let mut merged = to_prepend.clone(); merged.extend(existing);` — a prepend.
Candidates are `~/.bun/bin`, `~/.cargo/bin`, `~/.local/bin` (plus Homebrew), skipped only if
they don't exist — and an agent can create one. Every git probe then resolves `git` through it.
**Why it matters:** `mkdir -p ~/.bun/bin && cp evil ~/.bun/bin/git` gives code execution in the
PaneFlow process within seconds of the next launch, surviving agent restarts. Also hijacks
`open` (`workspace_ops/mod.rs:2397`) and the `which::which` lookup in `terminal/shell.rs:255`.
**Suggested fix:** Resolve `git` once at startup via `which::which` and store the absolute path
(or use `/usr/bin/git`); use `/usr/bin/open` literally. Separately **append rather than
prepend** — the stated goal ("user installs win") is met by appending; only the shadowing
behavior needs prepending, and that is the vulnerability.
**Verification:** Test asserting PATH augmentation appends, and that git spawns use an absolute path.

### 10. [HIGH] The shim rewrites seven user config files with no backup

### 20. [HIGH-perf] APCA contrast is recomputed per cell, per frame — ~10 `powf` minimum
**Location:** `src-app/src/terminal/element/mod.rs:1001-1003`; impl `element/color.rs:65-71`, `:79-111`, `:170-204`
**Problem:** `ensure_minimum_contrast` → `apca_contrast` → two `srgb_to_y`, each 3 `powf`, plus
up to 2 black-threshold and 2 SAPC exponents ≈ **10 `powf` per cell per frame** on the *fast*
path. On the slow path `adjust_lightness_for_apca` runs a 20-iteration binary search calling
`apca_contrast` each time, repeated for five desaturation multipliers (~1,200 `powf`, ~30–50 µs
for one character). `skip_contrast` already excludes truecolor and indices 16–255, so the key
space is at most ~576 pairs and a real screen uses 5–20.
**Why it matters:** ~8,000 cells in a maximized pane ⇒ **~3.5 ms per pane per frame**, 42% of a
120 Hz budget, inside `prepaint` on the main thread — for any pane showing ANSI-16 output
(`ls --color`, `git status`, most shell prompts).
**Suggested fix:** Memoize on `(raw_fg, raw_bg)` before the HSLA conversion, invalidated on
`theme::theme_generation()` (`theme/watcher.rs:92`) — the counter already exists.
**Verification:** `PANEFLOW_LATENCY_PROBE=1`, plus a new `prepaint` timer (the probe currently
times only `paint()`).

### 22. [MEDIUM-perf] `scan_output` lowercases ~20 KB on the main thread per terminal per 300 ms
**Location:** `src-app/src/terminal/pty_session.rs:2217-2250`; keywords `service_detector.rs:443`
**Problem:** ~200 `String` allocations, a 20 KB `join`, and a Unicode-aware
`str::to_lowercase` (~200–400 µs) — inside `this.update(cx, ...)`, i.e. on the GPUI main thread.
`top_limit` is `topmost_line()` (top of *scrollback*, not the viewport), so the loop can walk up
to 10,000 rows allocating two `String`s each, under the lock. Runs unconditionally even once
every port is in `reported_ports`, and fires for background-workspace terminals that never render.
**Why it matters:** 32 streaming panes ⇒ ~107 scans/sec ⇒ ~32 ms of main-thread CPU per second in
unpredictable bursts.
**Suggested fix:** Every keyword in `FRAMEWORKS` is ASCII — match case-insensitively over the
borrowed `&str` and drop the allocation; bound the upward walk to the viewport plus ~200 rows;
back off after N empty scans; move `detect_services_in_lines` to `cx.background_spawn`.

### 24. [MEDIUM-perf] Port scanning rebuilds the whole system process table once *per workspace*
